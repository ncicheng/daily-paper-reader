## 摘要
在对抗性环境中，由大语言模型辅助的自主机器人蜂群越来越多地被用于协同情报、监视与侦察（ISR）。日益增多的一类保障失败并非源于单个平台内部，而是跨越整个蜂群：个体合规的行为组合后可能导致任务级违规，例如：被禁止的目标被拆分到多个平台以规避每个平台的限制，或者集体预算被悄无声息地超支。每个平台的护栏在构造上就会遗漏这些问题，而对抗性通信环境会使违规行为隐藏在丢失或延迟的证据之后。我们提出了一个三层（平台/小队/任务）组合式运行时验证框架。该框架将任务策略分解为智能体个体层面和跨智能体层面，通过具备验证感知的消息传递架构聚合各平台的判定，并使用一种具有证据感知、双轴（安全性×完整性）的代数对其进行融合，该代数的溯源信息可以指出共同触发违规行为的平台。由于该架构使证据丢失和静默变得可观测，因此无法获得支持的否定判定会被降级为明确的“未知”状态，而不会报告为任务级全体通过。在模拟 ISR 任务中，一次间接提示注入导致真实 LLM 规划器将一个被禁止的采集任务拆分为四个平台执行，该违规行为对每个单独平台的监控器均不可见，但通过组合式验证却能检测到，并带有完整的溯源信息；在注入的故障测试中，尽力而为的中央监控器会静默地发出虚假的“全部清除”信号，而验证感知架构则不发出任何此类信号。

## Abstract
Swarms of LLM-assisted autonomous robots are increasingly proposed for cooperative intelligence, surveillance, and reconnaissance (ISR) in contested environments. A growing class of their assurance failures arises not within any single platform but across the swarm: individually-compliant actions compose into a mission-level violation: a prohibited objective split across platforms to evade per-platform lim- its, or a collective budget quietly exceeded. Per-platform guardrails miss these by construction, and contested communications let the violation hide behind lost or delayed evidence. We present a three-tier (platfor- m/squad/mission) compositional runtime-verification framework that de- composes a mission policy into per-agent and cross-agent aspects, aggre- gates per-platform verdicts over a verification-aware messaging fabric, and fuses them with an evidence-aware, two-axis (security x complete- ness) algebra whose provenance names the platforms that jointly trig- gered a violation. Because the fabric makes evidence loss and silence observable, unsupported negative verdicts are downgraded to an explicit unknown rather than reported as mission-wide all-clears. On a simulated ISR mission, an indirect prompt injection that causes real LLM planners to split a prohibited collection task across four platforms is invisible to every per-platform monitor yet detected compositionally with full prove- nance; under an injected fault campaign a best-effort central monitor emits silent false all-clears while the verification-aware fabric emits none

- **关键痛点**：
  - 个体合规的行为组合后构成集体违规，**平台级护栏在构造上无法发现**这类问题；
  - 对抗性通信环境（干扰、延迟、丢包）可导致违规证据被隐藏，使集中监控器发出误报性“全体通过”；
  - 缺乏将“任务是否被违反”与“是否有足够证据做出判断”分开处理的能力。
- **研究意义**：该问题在本质上具有**组合性**（需跨平台联合推理）和**证据敏感性**（丢失证据不能被视为好消息），因此需要一种新的任务级运行时保障框架，对蜂群的任务级义务进行持续、可审计的合规验证。

## 2. 方法论：核心思想、关键技术细节与公式

### 2.1 总体框架

- 提出**三层（平台/小队/任务）组合式运行时验证框架**：
  - **L1（平台层）**：在每个平台上运行局部监控器，判定空间驻留（如禁入区域）、一阶过去时间义务（如本地预算）、文本语义谓词（如授权传感器）；
  - **L2（小队层）**：小队协调器检查子群属性（联合区域占用、重复任务分配等）；
  - **L3（任务层）**：任务监控器消费L1/L2判定，决策跨智能体属性。

### 2.2 关键设计：验证感知织物（RV-Fabric）

- 底层通信基于 **MQTT**（平台到协调器）与 **NATS JetStream**（持久化后端）。
- 提供五项关键保证：
  1. **至少一次投递**（at-least-once delivery）；
  2. **单调排序**（monotone ordering，由协调器侧车分配可信时间戳与事件ID）；
  3. **任务时钟活性**（1 Hz后端驻留任务时钟，使静默平台可被感知为“缺失流”而非“空闲”）；
  4. **消费者隔离**（每消费者独立游标）；
  5. **流控**（背压/过载显式可观测）。

### 2.3 证据感知的双轴判定代数

- 任务判定为二元组 **(s, c)**：
  - **s = 安全性值** ∈ {violation, no_violation, unknown}；
  - **c = 完整性状态** ∈ {sound ≻ degraded ≻ incomplete ≻ unavailable}。
- **合成规则**：若完整性非sound，则no_violation被降级为unknown，绝不报告为任务级all-clear。
- 判定携带**溯源信息**：列出共同触发违规的平台及其见证事件ID，例如：
  ```json
  {
  "property": "prohibited_collective_intel_package",
  "verdict": "violation",
  "evidence_status": "sound",
  "agents": ["uav_1", "uav_2", "uav_3", "ugv_1"],
  "witnesses": ["uav_1-0", "uav_2-0", "uav_3-0", "ugv_1-0"]
  }
  ```

三个锚定评估的跨智能体属性：

- **Ppkg（禁止集体情报包）**：

### 2.5 攻击链与检测原理

- 攻击者通过**间接提示注入**（植入于检索到的情报数据中）使LLM规划器将禁止的Facility X情报收集拆分为四个平台各自执行一个片段；

## 6. 主要结论与发现

1. **检测有效性**：在攻击场景中，所有L1平台监控器均报告合规（0/3检测），而组合监控器成功检测全部3个任务级违规（禁止情报包、EMCON超支、未授权进入），并伴有准确的平台级溯源（6/6精确匹配）。
2. **零静默假全清**：在完整故障战役中：
   - 平台级护栏：9个静默假全清（无法表示跨智能体违规）；
   - 中央尽力而为监控器：3个静默假全清（丢证/干扰下误报全部通过）；
   - RV-Fabric：**0个静默假全清**（所有不确定均被显式标记为unknown/unavailable）。
3. **泛化性**：四种异质任务目标（语义组合、蜂群求和、跨智能体计数、因果链）均获得同样的结论——中央监控器被故障击穿，RV-Fabric保持零静默假全清。
4. **健全性**：良性任务下零误报；证据丢失只会导致“未知”，不会伪造“违规”或“通过”。
5. **可扩展性**：1000平台评估耗时1.2ms，远低于秒级任务决策预算。
6. **归因有效**：消融实验因果归因确认——移除G1会重新引入丢证下的静默遗漏，移除G3会重新引入干扰下的静默遗漏。

## 7. 优点

1. **问题定义精准**：清楚界定了“跨平台组合违规”这一新型保障失败类别，并论证其与单智能体安全防护的根本区别。
2. **双轴代数设计巧妙**：将安全性（violation判定）与完整性（证据充分性）解耦，从形式上保证“诚实未知”优先于“虚假确认”，切中对抗通信环境的核心痛点。

5. **评估兼顾三个层面**：
   - 受控的可复现核心（固定种子确定性实验）；
   - 真实中间件验证（MOSQUITTO + JetStream端到端）；

   - 核心定量结果来自确定性运动学仿真，而非真实物理环境或大规模实地试验；
   - Gazebo可视化渲染未启用；
   - 未开展更大规模的物理、多平台部署试验。
2. **威胁模型假设较窄**：
   - 核心模型假设认证身份但可能静默的平台；平台被完全攻破（撒谎）超出核心范围（仅有一个探索性RF证人扩展）；
   - 假定链路密码学安全（身份伪造在信任边界之外）；
   - 未考虑恶意监控器或LLM被深度操纵后伪造事件流的情况。
3. **形式化证明不完整**：双轴代数的健全性论证仅以条件性论证形式呈现（借鉴自边缘IoT工作），**完整的组合代数形式化证明留作未来工作**。
4. **LLM实验可复现性受限**：论文注明LLM输出“被保存但不可保证可复现”（托管模型可能变化），影响该部分的独立复现性验证。
5. **语义提取为辅助路径**：自由文本协调消息映射到谓词的语义提取器被标记为“次级路径”，文本-only违规检测依赖分类器质量，未作为核心结果验证。
6. **静态任务策略假设**：监控器针对固定任务策略验证，若策略本身配置过松（如预算设得过高），框架无法防止违规（残余风险在表1中明确标注）。
7. **时机语义存在盲区**：低慢（low-and-slow）自适应攻击可跨任务拆分布局，当前窗口化监控在窗口小于攻击跨度时失效（作者已在7.6节自认此限制）。

## 总结

该论文针对LLM辅助自主蜂群在对抗环境下特有的**跨平台组合违规**问题，提出了一个理论动机清晰、工程实现完整、评估层次丰富的三层组合式运行时验证框架。其核心贡献在于：将任务级保障从“单平台安全”提升到“蜂群级义务验证”，并通过证据感知的双轴判定代数与验证感知织物，从根本上杜绝了“因证据缺失而误报全体通过”这一任务保障最危险的失效模式。虽然在物理实验覆盖与形式化证明深度上仍有提升空间，但作为M&S方法论框架，其对任务级组合保障的理论洞察、实现完整性和防御有效性已经呈现出较显著的研究价值。
